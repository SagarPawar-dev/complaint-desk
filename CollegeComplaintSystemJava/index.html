RESOLUTION WORKFLOW

How campus grievances move from report to resolution

No lost paperwork, forgotten emails, or unrecorded verbal complaints. Every report follows a verified, transparent lifecycle.

1

Student Submits Grievance

The student selects the category (IT, Electrical, Facilities, Plumbing), specifies the exact campus location, and describes the issue.

STATE: PENDING
2

Administrative Assessment

Campus administrators review the ticket in the centralized management queue, assess severity, and assign inspection priority.

TRIAGE & REVIEW
3

Active Remediation & Audit

Maintenance staff are dispatched. Administrators update the ticket status with timestamped remarks, triggering student notification badges.

STATE: IN PROGRESS
4

Verified Ticket Closure

Once repairs are inspected, the ticket is transitioned to Resolved or Closed with full chronological audit records permanently preserved.

STATE: RESOLVED
PLATFORM CAPABILITIES

Purpose-built for campus institutional governance

Engineered with enterprise-grade Java Servlets, strict server-side authorization, and relational database integrity.

Structured Categorization

Pre-configured campus categories ensure issues reach the right facilities and IT personnel without manual sorting delays.

  • IT & Laboratory Equipment
  • Electrical & Power Systems
  • Campus Premises & Plumbing

Monotonic Sequential IDs

Every ticket receives a persistent formatted identifier (CMP-0000X) managed by database-backed sequences that never reuse deleted IDs.

  • Concurrency-safe sequence generation
  • No duplicate or regressing ticket numbers
  • Permanent institutional reference

Chronological Timeline Audit

Every administrative remark, priority alteration, and lifecycle transition is permanently recorded in the complaint timeline table.

  • Timestamped logging with user identity
  • Administrative remarks & inspection notes
  • Immutable resolution audit trail

In-App Notification Center

Real-time unread notification counters in the top navigation header inform students immediately whenever their grievance status advances.

  • Header bell badge with live unread counter
  • One-click 'Mark All as Read' feature
  • Direct link from alert to complaint details

Server-Side Session Security

Tomcat HttpSession with HttpOnly cookies, Java security filters, and strict role isolation prevent tampering or unauthorized access.

  • AuthenticationFilter guards protected paths
  • Students cannot access /admin/* endpoints
  • Server-derived identity prevents ID spoofing

Profile & Settings Sync

Students can update their profile information with immediate PostgreSQL database persistence that remains consistent across sessions.

  • Validated input with user ID from session
  • Instant update across dashboard greetings
  • Persists after logout and fresh logins
AUDIT & PLATFORM INTEGRITY

Built on principled institutional governance

Ensuring that every reported issue is held to strict operational standards with immutable database audit trails.

Transactional Consistency

All database operations execute within strict ACID-compliant transactions on Supabase PostgreSQL. Status updates and timeline entries commit atomically or roll back cleanly.

Role-Based Authorization

Security is enforced in Java Servlets on the server side, not merely in the browser UI. Students attempting to call administrative delete or status endpoints receive HTTP 403 Forbidden.

Persistent ID Tracking

Complaint ticket IDs are generated via dedicated database sequences. Even if a ticket is removed by administrators, deleted IDs are never reused, preserving sequence integrity.
